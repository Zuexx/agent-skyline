# 視覺語言規格(草稿)

狀態:2026-10-23 草稿,給使用者審。方向確認後再補英文版,並據此修改 `06-themes.md`、`07-work-view.md`。

這份規格定義「每一件事在畫面上長什麼樣子」。美術(`sprite-poc` 的素材流程)和程式都照它做。它要避免的問題是:**用一種表現吃全套**。每種事情都要有自己的樣子,一眼就能分辨。

---

## 0. 原則

1. **一件事一個樣子。** 讀、寫、搜尋、執行、測試、擋下、等待,各有各的動作和特效,不共用。
2. **三段距離,三種讀法。**
   - 遠看(小鎮全景):只看「哪裡在忙、哪裡出事」。靠顏色、光、煙、旗子這些大訊號。
   - 走近(拉近或進入建築):看「在做什麼」。靠角色動作和擺設。
   - 細看(點選):看「精確內容」。交給面板的文字,不靠畫面。
3. **場景不動,資訊疊上去。** 小鎮的版面和畫好的背景在切換視角時都不變;變的是疊在上面的物件、特效、霧、旗子。使用者腦中的地圖不會被打亂。
4. **顏色語意全域固定**,畫面、面板、清單都一樣:

   | 顏色 | 意思 |
   |---|---|
   | 藍 | 讀取、資訊 |
   | 琥珀 / 火光 | 寫入、施工 |
   | 紅 | 擋下、禁區、失敗、危險 |
   | 綠 | 通過、新增、完成 |
   | 紫 | 「它用到誰」 |
   | 粉紅 | 「誰用到它」 |
   | 灰 / 霧 | 沒碰過、閒置 |

5. **不只靠顏色。** 每個狀態同時有形狀或圖示(旗子、煙、「！」、瓦礫),色弱也分得出來。
6. **動得越多,代表越重要。** 擋下、失敗、衝突的動作最大;閒置的環境動畫(炊煙、鳥、NPC)最輕微,不能搶戲。
7. **同一件事永遠同一個樣子**,不管在哪一層、哪個視角。
8. **光一律從左上來。** 所有素材一致,夜間由程式調光,不另外畫夜景素材。

## 1. 三層

| 層 | 畫面 | 一個單位是 | 回答的問題 |
|---|---|---|---|
| 1 小鎮 | 整個 repo 的 HD-2D 城鎮 | 一棟建築 = 一個資料夾 | agent 在哪一區?哪裡出事? |
| 2 室內 | 點建築後進入的室內場景 | 一個擺設 = 一個檔案;一個房間 / 樓層 = 一個子資料夾 | 它在動哪幾個檔案? |
| 3 檔案 | 詳細面板(文字) | 一個檔案 | 改了什麼?誰依賴它? |

- 進出:點建築推進室內;室內的「出口」回到小鎮;室內通往其他資料夾的「門」直接走到那棟建築。
- 鏡頭在第 1、2 層都是 HD-2D 的低角度透視加景深;第 3 層是面板,不動鏡頭。

## 2. 小鎮(第 1 層)的語彙

### 2.1 建築

| 資料夾的主要角色 | 建築 | 小 / 中 / 大(依檔案數) |
|---|---|---|
| 程式碼 | 鍛冶屋 / 工坊 | 小鐵匠鋪 / 鍛冶屋 / 大工坊(多座熔爐) |
| 測試 | 瞭望塔 / 訓練場 | 哨亭 / 瞭望塔 / 要塞 |
| 文件、規格 | 圖書館 | 書報亭 / 圖書館 / 大學院 |
| 設定 | 鐘樓 / 教會 | 小祠 / 鐘樓 / 大教會 |
| 資源(圖片、影片) | 市集倉庫 / 蘑菇屋 | 倉庫 / 商行 / 市集 |
| repo 根目錄 | 鎮公所(廣場中心) | 只有一種 |

- **變體**:每種每個大小 2–3 個變體,依資料夾路徑固定選一個。同類建築重複出現時不會一模一樣,但同一個資料夾永遠長同一個樣子。
- **大小**依檔案數(這個 repo 自己的三等分),不是行數。
- **招牌**:建築前立木牌,寫資料夾名稱。由程式疊上去,不畫進圖裡。
- **太小的資料夾**(1–2 個檔案)不單獨蓋建築,併到它的上層資料夾,當作那棟建築旁的小棚子。整個 repo 的建築數控制在大約 12–40 棟。

### 2.2 路(依賴關係)

| 資料 | 表現 |
|---|---|
| A 資料夾的檔案 import B 資料夾的檔案 | A 和 B 之間有一條路 |
| import 數 1–2 / 3–9 / 10 以上 | 泥土小徑 / 石板路 / 大道 |
| 互相依賴 | 雙線道 |
| 選取一棟建築 | 它用到誰的路亮紫色,誰用到它的路亮粉紅,其他路變暗 |
| 平常 | 只顯示最粗的 15 條左右;選取時才顯示該建築全部的路 |

- **版面由路決定**:互相依賴多的資料夾排得近(力導向排版),同一個上層資料夾的建築圍成一個街區。孤立的資料夾在郊外。根目錄的鎮公所在中央廣場。

### 2.3 地形與環境

| 元素 | 用途 |
|---|---|
| 中央廣場 | repo 根目錄;agent 閒置時回到這裡 |
| 街區(石板地) | 同一個上層資料夾 |
| 郊外(草地、樹林) | 孤立的資料夾;畫面邊緣的留白,讓資訊卡疊上去不擋建築 |
| 訓練場 | 跑測試的地方(跟著測試建築) |
| 長椅 | agent 等待回覆時坐的地方 |
| 鎮民 NPC、炊煙、鳥、水車 | 環境動畫;沒有 agent 工作時城鎮也是活的。不代表任何資料,而且可以關掉 |

## 3. Agent 的語彙

### 3.1 誰是誰

| 來源 | 角色 |
|---|---|
| Claude Code 主 agent | 勇者、魔法使、僧侶……依出現順序分配,每個 agent 一種主色 |
| 子 agent(subagent) | 主 agent 身邊的小精靈 / 跟班,同色系,體型較小 |
| pi | 另一種職業(例如商人或騎士),跟 Claude 一眼分得出來 |
| 檔案監看(沒有 agent 的改動) | 沒有角色;只在建築上冒一陣灰煙 |

- 腳下有主色的光圈;頭上有名牌(Claude 1、pi 1)。
- 走過的路留下主色的發光腳印,幾秒後消失。

### 3.2 動作(每一種都不同)

| 事件(資料) | 動作 | 地點 | 特效 | 持續 |
|---|---|---|---|---|
| 接到指令(prompt) | 抬頭、驚嘆號一閃,從廣場出發 | 廣場 | 頭上冒出指令的對話框(前 20 字) | 3 秒 |
| 讀檔(read) | 翻書 | 該建築門口;室內在該擺設前 | 窗戶亮藍光 / 擺設發藍光 | 讀取後 4 秒 |
| 搜尋(Grep、Glob) | 拿望遠鏡左右看 | 原地 | 被搜到的建築依序閃一下藍光 | 2 秒 |
| 寫檔(write) | 敲打 | 該建築前 | 冒火花;建築搭鷹架(見 4) | 敲打 2 秒;鷹架持續 |
| 執行一般指令(exec) | 施法 | 原地 | 腳下出現魔法陣 | 2 秒 |
| 跑測試、建置(check) | 走到訓練場打木人 | 訓練場 | 結果見 4 | 跑完為止 |
| 被禁區擋下(blocked) | 撞上結界被彈回、跌坐 | 結界邊 | 頭上冒紅「！」;結界閃一下 | 3 秒 |
| 寫到允許範圍外(越界) | 正常敲打,但頭上冒黃「？」 | 該建築前 | 建築插黃色警示旗 | 旗子持續到 review |
| 兩個 agent 改同一個檔案 | 兩人面對面、頭上冒火花對撞 | 該建築前 | 建築上方交叉的兩把鎚 | 5 秒,旗子持續 |
| 等待回覆(Stop) | 走到長椅坐下打瞌睡 | 最近的長椅 | 「zzz」 | 直到下一個指令 |
| 任務完成(Stop 且這輪有寫入) | 舉手歡呼,再去坐長椅 | 原地 | 小煙火 | 2 秒 |
| 移動到另一棟建築 | 沿著路走;距離遠就跑 | 路上 | 腳印 | 依距離 |
| 10 分鐘沒動靜 | 慢慢淡出 | — | — | — |

## 4. 檔案與 repo 狀態的語彙

這些不需要 agent 在場也看得到,在小鎮上顯示在建築上,室內顯示在擺設上。

| 狀態 | 資料來源 | 小鎮(建築) | 室內(擺設) | 持續 |
|---|---|---|---|---|
| 未 commit 的修改 | `/api/working` M | 鷹架;改越多鷹架越高 | 擺設蓋著帆布、工具散落 | 到 commit 為止 |
| 新增的檔案 | `/api/working` A | 旁邊的空地出現地基和帳篷 | 新的木箱,標「新」 | 到 commit 為止 |
| 刪除的檔案 | `/api/working` D | 建築旁的瓦礫堆 | 擺設的位置留下瓦礫 | 到 commit 為止 |
| 改名 / 搬移 | `/api/working` R | 搬家馬車從舊建築駛向新建築 | 擺設被推走 | 一次動畫,之後同新增 |
| 大規模改動(一輪改了 10 個以上檔案) | 事件 | 吊車加好幾座鷹架 | — | 到 commit 為止 |
| 測試通過 | 執行結果 passed | 測試建築升綠旗 | — | 到下一次測試 |
| 測試失敗 | 執行結果 failed | 測試建築冒黑煙、起小火 | — | 到下一次測試 |
| 測試結果不明 | 執行結果 unknown | 白旗 | — | 到下一次測試 |
| 熱點(90 天內常被改) | `/api/churn` | 門口有市集攤位、人來人往 | 擺設磨損發亮 | 持續 |
| 很久沒人動 | **沒有資料**:要新增「每個檔案最後 commit 時間」 | 長青苔、爬藤蔓 | 擺設積灰、蜘蛛網 | 持續 |
| 被很多檔案依賴 | `/api/deps` | 建築較高的基座、門口有旗桿 | 擺設較大 | 持續 |
| 禁區(locked) | `/api/zones` | 紅色魔法結界罩住整棟 | 室內門口有封印,進不去 | 持續 |
| 宣告的任務範圍 | `/api/scope` | 範圍內的建築地面亮淡綠色的圈 | — | 持續 |
| commit 發生 | **沒有資料**:要監看 `.git` 的 HEAD | 鐘樓響鐘;郵差馬車從鎮公所出發;鷹架拆掉 | — | 一次動畫 |

**同一棟建築同時有好幾個狀態時**:
1. 優先順序:擋下、失敗、衝突 > 寫入中 > 越界 > 讀取中 > 持續性狀態(熱點、青苔……)。
2. 最多同時顯示 2 個特效,其他的收成建築上方的小徽章加數字。
3. 禁區結界永遠顯示,不算在 2 個裡面。

## 5. 視角(地圖模式)

版面和背景不變,換的是疊在上面的東西。工具列的「資料夾 / 角色 / 本次動過 / 差異」對應如下。

| 模式 | 疊上去的東西 | 隱藏或淡化的東西 | 回答的問題 |
|---|---|---|---|
| 資料夾(預設) | 第 2、3、4 節全部 | — | 整體狀況 |
| 角色 | 每棟建築掛行會旗:鐵鎚(程式碼)、盾牌(測試)、書本(文件)、齒輪(設定)、錢袋(資源);地面鋪角色的淡色塊 | 持續性狀態的特效 | 改了程式碼有沒有補測試? |
| 本次動過 | **戰爭迷霧**:這次工作沒碰過的建築罩在霧裡;讀過的撥開霧;改過的亮燈加鷹架;agent 的足跡保留整段工作 | 熱點、青苔等持續性狀態 | 這次 agent 看過哪裡、動過哪裡? |
| 差異(比較分支) | 施工圖:新增 = 新建築掛「新」字招牌;修改 = 鷹架;刪除 = 廢墟;沒變的建築變成淡淡的線稿 | agent、即時事件 | 這個分支改了什麼? |

- 切換時有轉場:霧從四周捲進來、旗子一面面升起,大約 0.6 秒,不會一瞬間跳掉。
- 依角色重新排列的那種畫面,另外做成一張小的「行會分布圖」(2D、可選),不動主場景。

## 6. 室內(第 2 層)的語彙

| 建築 | 一個檔案 | 大檔案 | 子資料夾 |
|---|---|---|---|
| 鍛冶屋 | 工作台 / 鐵砧 | 大熔爐 | 不同的作業區 |
| 瞭望塔 | 一個哨位 | 高一點的樓層 | 一層樓 |
| 圖書館 | 書架 | 整面書牆 | 閱覽室 |
| 鐘樓 | 齒輪 / 機關 | 大鐘 | 一層樓 |
| 倉庫 | 貨架 / 木箱 | 大貨櫃 | 隔間 |

- 連到其他資料夾的依賴:門,門上寫「→ server(3)」;點門走到那棟建築,對應的擺設標亮。
- agent 的動作和第 3.2 節相同,只是地點換成該擺設前。

## 7. 文字與 UI

- 畫面上的文字只有:資料夾招牌、agent 名牌、指令對話框、徽章數字。全部由程式疊上,用像素字型,不畫進素材。
- 面板(KPI 卡、任務進度、清單、詳細面板)沿用 DQ 視窗風格:黑底、白框、像素字。
- 動態清單改成戰鬥訊息的口吻:「Claude 1 翻開了 JwksProvider.cs!」「僧侶被結界彈開了!」。

## 9. 動態的取捨

- **降低動態**的設定:關掉環境動畫(NPC、鳥、炊煙),事件特效縮短一半。

- 同一時間最多 3 個大型特效(煙火、吊車、結界閃光);超過的排隊或略過。

## 11. 背景怎麼畫出來

依 2B 的做法(`D:\ComfyUI\Output\sprite_poc\deliver\README.txt`):

1. 依第 2 節排出版面,用建築 sprite 擺成一張「版面圖」,同時輸出深度圖和線稿當控制圖。
2. Qwen-Image 依控制圖重畫成一整張 HD-2D 小鎮。建築位置被控制圖固定,所以每棟畫出來的建築都對得回它的資料夾。
3. MoGe-3 從畫算出深度和幾何,轉成 2.5D 浮雕;路燈位置放真實光源,景深依真實深度。
4. 第 3、4 節的角色、特效、旗子、霧、招牌在引擎裡即時疊上去。
5. 資料夾結構大改時才重畫背景。新出現的資料夾在重畫之前,先用建築 sprite 頂著。

所以建築 sprite 有兩個用途:排版面圖,以及重畫前的暫代建築。
